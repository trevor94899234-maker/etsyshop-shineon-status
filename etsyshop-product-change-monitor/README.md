# EtsyShop Product Change Monitor

An independent snapshot monitor for the EtsyShop product families that matter most operationally:

- `Graphic Journal`
- Acrylic Plaque variants listed in the supplied ShineOn prices sheet

The monitor compares successful snapshots and reports changes to subscription-tier product cost, regional shipping price, shipping time, category production range, ShineOn overall status and component status.

The page places a `ShineOn System Status` panel near the top. It uses the public summary and components APIs to show the green/yellow/red status meaning, active incidents, active maintenances, each component's original name/status/group, fetched time, and whether status fields changed since the previous successful snapshot. When the API omits `activeIncidents` or `activeMaintenances`, the panel says `Field not provided`; it does not invent a zero.

The page displays only the owner's Enterprise Builder tier. The supplied sheet's original field is retained as `Empire Builder` in the saved JSON and is mapped to the display label `Enterprise Builder`.

The page opens with four compact, color-separated views: ShineOn System Status, Fulfillment window, Product cost, and Shipping catalog. Each view is collapsed by default and shows a compact status summary; clicking it expands the details. Product cost contains Acrylic Plaque and General (non-Acrylic, currently Graphic Journal) cost lists. Shipping catalog contains Acrylic Plaque and General (currently Journal) shipping catalogs with regional prices and delivery windows.

The visual sections use consistent accents: warm amber marks product cost, teal marks fulfillment, and slate blue marks shipping catalog sections.

## Sources

- [Production and Sync Timescales & Info](https://teamshineon.zendesk.com/hc/en-us/articles/10262194743441-Production-and-Sync-Timescales-Info)
- [Shipping Timescales, Prices & Info](https://teamshineon.zendesk.com/hc/en-us/articles/10281047558545-Shipping-Timescales-Prices-Info#Variable)
- [ShineOn Prices + Shipping Google Sheet](https://docs.google.com/spreadsheets/d/1RapLC3WTjaDLePDZszpRh8SzBj0SNzhiTtySueTOpvE/edit?gid=170660766#gid=170660766)
- [ShineOn status summary API](https://status.shineon.com/v3/summary.json)
- [ShineOn status components API](https://status.shineon.com/v3/components.json)
- [ShineOn source terms](https://status.shineon.com/en/terms)

The script uses the two public ShineOn status APIs, the public Zendesk Help Center JSON endpoints to read the two article bodies, and the public CSV export of the supplied Google Sheet. The production article gives category ranges: Graphic Journal is 2–3 business days and acrylic products are 3–5 business days. The shipping article gives regional time guidance; the sheet supplies product/tier shipping prices. The sheet's `EU` labels are matched to the article's international standard/priority time labels and are marked in the saved source notes.

## Run locally

From this folder:

```text
node scripts/fetch-etsyshop-product-data.mjs
python -m http.server 8787
```

Then open `http://127.0.0.1:8787/`. Double-clicking `index.html` is not a valid test because the browser may block its relative JSON fetch from a `file:` URL.

The local URL works only while the `python -m http.server 8787` process remains running.

`data/product-status.json` is generated by the fetch script. The script writes a temporary file and replaces the previous snapshot only after all five sources pass; a failed fetch exits with code 1 and leaves the previous snapshot intact.

The fulfillment visualization shows planning windows from the supplied sources; it is not an order-specific ship-date calculator.

## Comparison behaviour

The first successful run creates a `baseline`. Later successful runs compare field values by `productKey`. A change record keeps the product, field label, previous value, current value and direction. Missing source cells remain `null` or the source's explicit `Not Available` value; they are not converted into zero.

The parent repository workflow refreshes this snapshot every six hours and deploys this page at the Pages root. The previous ShineOn status page is kept at `/shineon-status/`. The workflow and Pages behaviour still require a real GitHub run before they can be called verified.
